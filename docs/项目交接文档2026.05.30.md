# 项目交接文档2026.05.30

## 1. 项目总体目标

- 本项目的长期目标：以 **ViDiT-Q** 作为底层工程框架，对 **OpenSora v1.2 / STDiT3** 模型做视频扩散模型的缓存优化研究。
- 用户确定的研究方向：参考 **TeaCache / Timestep Embedding Tells It's Time to Cache for Video Diffusion Model** 的核心思想，研究 timestep embedding 与中间特征变化之间的关系，并将缓存机制加入 OpenSora 推理流程。
- 当前阶段的主要任务：先完整跑通 ViDiT-Q 中 OpenSora v1.2 的原始 FP16 推理链路，然后再进入 ViDiT-Q 量化实验复现，最后再考虑 TeaCache 插桩与优化。
- 最终希望达到的效果：
  - 可稳定在用户本机 RTX 5080 Laptop GPU 上运行 OpenSora v1.2 推理。
  - 可复现 ViDiT-Q 论文中的量化实验。
  - 在 OpenSora / STDiT3 上加入 timestep-aware cache，并比较速度、显存、质量损失。

### 16 帧 NaN 问题定位

- 现象：
  - 1 帧可以跑。
  - 16 帧推理会出现 NaN。
- 根因已验证：
  - `Open-Sora/opensora/schedulers/rf/rectified_flow.py` 中 `timestep_transform()` 使用：
    ```python
    num_frames = model_kwargs["num_frames"] // 17 * 5
    ```
  - 当 `num_frames=16` 时：
    ```text
    16 // 17 * 5 = 0
    ```
  - 第一个 timestep 处出现 `0 / 0`，导致 NaN。
- 解决：
  - 使用 `num_frames=17`。
  - 当前推荐配置：`configs/local_144p_17f.py`
- 已验证：17 帧 10 step 推理成功。

### 问题 1：WSL2 中 `nvidia-smi` Segmentation fault

  ```text
  nvidia-smi
  ```

- 已验证：
  ```bash
  nvidia-smi

  ```
  均正常。

### 问题 2：Conda Terms of Service 未接受

- 现象：
  ```text
  CondaToSNonInteractiveError: Terms of Service have not been accepted
  ```
- 解决：
  ```bash
  conda tos accept --override-channels --channel https://repo.anaconda.com/pkgs/main
  conda tos accept --override-channels --channel https://repo.anaconda.com/pkgs/r
  ```
- 状态：
  - 已解决。

### 问题 3：`pip install xformers` 自动升级 torch 导致冲突

- 现象：
  - 安装 xformers 时自动拉取 `torch 2.11.0+cu128`。
  - 导致：
    ```text
    torchaudio 2.8.0+cu128 requires torch==2.8.0
    torchvision 0.23.0+cu128 requires torch==2.8.0
    ```
- 根因：
  - pip resolver 不会可靠保持 torch/torchvision/torchaudio/xformers 成套版本。
- 当前解决：
  - 主环境固定为：
    ```text
    torch 2.8.0+cu128
    torchvision 0.23.0+cu128
    torchaudio 2.8.0+cu128
    xformers 0.0.32.post2
    ```
- 状态：
  - 已解决。

### 问题 4：OpenSora `requirements.txt` 会覆盖 torch

- 现象：
  - 安装 `requirements/requirements.txt` 后 torch 被降级到 `2.2.2`。
  - 报冲突：
    ```text
    torchaudio 2.8.0+cu128 requires torch==2.8.0
    xformers 0.0.32.post2 requires torch==2.8.0
    ```
- 根因：
  - OpenSora requirements 中存在旧版 torch 相关依赖，或依赖链拉取旧 torch。
- 当前策略：
  - 不再直接安装完整 requirements。
  - 对长期环境也不建议直接跑 `pip install -r requirements/requirements.txt`。
  - 采用手动安装依赖清单，禁止覆盖 torch/torchvision/torchaudio/xformers/triton/nvidia-*。
- 状态：
  - 已解决策略，但后续新环境仍需谨慎。

### 问题 5：`huggingface_hub==1.15.0` 与 diffusers 不兼容

- 现象：
  ```text
  ImportError: cannot import name 'cached_download' from 'huggingface_hub'
  ```
- 触发条件：
  - `huggingface_hub` 被升级到 `1.15.0`。
- 根因：
  - `diffusers 0.27.2` 仍依赖 `huggingface_hub.cached_download`。
  - 新版 `huggingface_hub` 已移除该接口。
- 解决：

- 注意：
  - 会与 gradio / peft 的新版本声明产生冲突，但当前 OpenSora 推理路径不依赖 gradio。
- 状态：
  - 已解决并验证。

### 问题 6：VAE / STDiT checkpoint 加载路径错误

- 现象：
  ```text
  RuntimeError: Invalid checkpoint path .../OpenSora-VAE-v1.2/model. Expected a file or a directory.
  RuntimeError: Invalid checkpoint path .../OpenSora-STDiT-v3/model. Expected a file or a directory.
  ```
- 触发条件：
  - 使用 HuggingFace safetensors 权重，但 OpenSora 默认按 ColossalAI sharded checkpoint 加载。
- 根因：
  - `load_checkpoint()` 默认找 `model/`。
- 解决：
  - 配置中加入：
    ```python
    force_huggingface=True
    ```
- 状态：
  - 已解决并验证。

### 问题 7：主环境 xFormers default backend 在 RTX 5080 报 CUDA invalid argument

- 现象：
  ```text
  CUDA error (.../flash-attention/hopper/flash_fwd_launch_template.h:188): invalid argument
  ```
- 触发条件：
  - 主环境：
    ```text
    torch 2.8.0+cu128
    xformers 0.0.32.post2
    RTX 5080 / sm_120
    ```
  - OpenSora 使用 xFormers default dispatch。
- 根因：
  - 已验证：当前 xFormers wheel 的 default/flash 路径对 Blackwell 支持不稳定。
  - 推测：xformers 0.0.32 的 flash-attention kernel 对 `sm_120` 不完整。
- 解决：
  - 主环境使用：
    ```bash
    export VIDITQ_XFORMERS_OP=cutlass
    ```
- 状态：
  - 已解决并验证。

### 问题 8：SDPA fallback 1 帧可跑但 16 帧 NaN

- 现象：
  - 暂时绕开 xFormers 后，1 帧可跑，16 帧出现 NaN。
- 已排除：
  - 不是 VAE decode 导致。
  - 不是简单随机数或输出保存导致。
- 根因：
  - 最终定位到 16 帧与 timestep transform 不兼容，而不是 SDPA 单独问题。
- 状态：
  - 不建议继续走 SDPA fallback 作为主路线。

### 问题 9：纯 T2V 空 mask 误触发 x_mask

- 现象：
  ```text
  AssertionError
  ModuleNotFoundError: No module named 'ipdb'
  ```
- 触发条件：
  - `mask_strategy=[""]`
  - `num_frames=16/17` 等多帧推理。
- 根因：
  - 空字符串 mask 被当成有效 mask 处理。
- 解决：
  - `apply_mask_strategy()` 空 mask 直接返回 `None`。
- 状态：

### 问题 10：16 帧与 `use_timestep_transform=True` 不兼容
